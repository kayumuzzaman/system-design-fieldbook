Layers: who is responsible for what

Chapter 2 followed one request from a browser to a server. It skipped over a question that this part of the book answers: how do the bytes actually cross the network? The answer is organized in layers. Each layer solves one problem and relies on the layer below for everything else.

  • The link layer moves a frame between two machines that are directly connected: your laptop and the Wi-Fi router, or two routers joined by a fiber.
  • The internet layer, the subject of this chapter, moves a packet across many links from any machine to any other, using IP addresses.
  • The transport layer turns unreliable packets into something programs can use, such as an ordered stream of bytes. covers it.
  • The application layer is the protocol your code speaks. and the chapters after it cover those.
Why “layer 4” and “layer 7”The numbers come from the OSI model, a seven-layer reference design from the 1980s. The internet uses a simpler four-layer stack, and the OSI numbers survived as vocabulary. You will hear them constantly: a “layer 4 load balancer” forwards by IP address and port without reading the request, and a “layer 7” one understands HTTP. Layers 5 and 6 are almost never mentioned.

The value of layering is that each layer can change without the others noticing. HTTP runs unchanged over Wi-Fi, fiber or a mobile network. A router forwards a packet without knowing or caring whether it carries a web page or a video call.

IPv4 addresses and CIDR

An IPv4 address is a 32-bit number. For people it is written as four decimal numbers from 0 to 255 separated by dots, one per byte: 203.0.113.10. Thirty-two bits give 232, about 4.3 billion, possible addresses.

An address has two parts. The leading bits identify a network, and the remaining bits identify a host within it. This split is what makes routing workable: a router far away needs one entry for the whole network, not one for every machine in it.

Where the split falls is written with CIDR notation (classless inter-domain routing): an address, a slash, and the number of leading bits that belong to the network. 10.0.0.0/20 means “the first 20 bits are the network, the remaining 12 are for hosts”.

A larger number after the slash means a longer network part and therefore a smaller block. Each extra bit halves it.

Common mistake. Binding a service to 0.0.0.0 when it was meant to be reachable only locally. Bind internal services to a private address or to 127.0.0.1, and treat the firewall as a second line of defense.

Running out of addresses

Four billion addresses were plenty in 1981. They are far fewer than the number of phones, laptops, servers and sensors now connected. The central pool of unallocated IPv4 addresses was handed out completely in February 2011, and the regional registries that distribute addresses to providers ran dry over the following years: North America’s in 2015, Europe’s in 2019.

The internet kept growing anyway, by three means that every system designer now has to deal with.

  • Sharing. Many machines sit behind one public address, using network address translation. This is the subject of the next section.
  • Trading and charging. Addresses are bought and sold, and cloud providers bill for them. Since February 2024 AWS has charged $0.005 per hour for every public IPv4 address, about $44 a year each. A fleet of a thousand servers with public addresses pays that a thousand times over, which is one more reason to keep servers on private addresses behind a load balancer.
  • IPv6. A new version of the protocol with a far larger address space, described later in this chapter.

NAT: many machines behind one address

Network address translation (NAT) lets machines with private addresses reach the internet through a shared public one. A device at the edge of the private network, such as your home router or a cloud NAT gateway, rewrites packets as they pass.

When the laptop opens a connection, the gateway replaces the packet’s private source address and port with its own public address and an unused port, and records the pair. When the reply arrives at that port, it reverses the substitution. The server never learns the private address. It sees a connection from 198.51.100.7.

NAT is why the internet still works, and it has consequences that surface in design work again and again.

ConsequenceWhyWhere it bites
Connections can only start from insideA mapping exists only after an inside machine has sent something. An unsolicited packet from outside matches nothing and is dropped.Peer-to-peer calls and games need helper servers to connect two machines that are both behind NAT. See .

Providers add a second layer, carrier-grade NAT, which puts thousands of customers behind each one.Rate limiting or blocking “by IP address” punishes everyone behind it. The same mechanism runs in the other direction on purpose. A port forwarding rule tells the gateway that anything arriving on public port 443 goes to a particular private machine. A load balancer with a public address in front of private servers is the grown-up version of that idea.

IPv6

IPv6 replaces the 32-bit address with a 128-bit one. That is enough for 3.4 × 1038 addresses, which removes scarcity as a design constraint altogether.

An IPv6 address is written as eight groups of four hexadecimal digits separated by colons. Leading zeros in a group may be dropped, and one run of all-zero groups may be replaced by a double colon:

2001:0db8:0000:0000:0000:0000:0000:0010 in full 2001:db8::10 the same address, shortened

The conventions differ from IPv4 in ways that matter in practice.

  • Subnets are almost always /64. The first 64 bits identify the network and the last 64 the interface. A single subnet holds 264 addresses, so sizing subnets stops being a concern.
  • NAT is unnecessary. Every device can have a globally unique address. Reachability is then controlled by firewalls alone, which need to be configured with that in mind: there is no NAT acting as an accidental barrier.
  • A device has several addresses. A link-local one starting fe80: for its own network segment, usually one or more global ones, and often temporary ones that change for privacy.
  • Customers receive whole blocks. A home connection is typically given a /56 or /64, so one household can produce an effectively unlimited number of addresses.

IPv4 and IPv6 are separate protocols that do not interoperate directly. The usual arrangement is dual stack: a machine has both kinds of address, and DNS returns both an A and an AAAA record. The client tries both and uses whichever connects first, a technique known as Happy Eyeballs. Some networks, mobile ones in particular, are now IPv6 only inside and translate at the edge to reach the IPv4 internet.

How far along is it?It depends on who is counting. Google saw IPv6 from half its users for the first time in March 2026. Cloudflare, which counts requests rather than users, reported that under a third of requests able to use either protocol chose IPv6 during 2025. Mobile networks are far ahead of corporate ones, and India is far ahead of most countries.

For a designer the practical points are few and easy to get wrong:

  • Store addresses in a type made for them. A column sized for 255.255.255.255 is too small, and an integer column cannot hold 128 bits. Use the database’s IP address type, or allow 45 characters of text.
  • Rate limit and block by /64, not by single address. One user can change the low 64 bits at will.
  • Check every place that parses an address. Log pipelines, allow lists, geolocation lookups and validation code are where IPv6 support usually turns out to be missing.
  • Serve both. A public endpoint without an AAAA record forces IPv6-only users through a translator. Most CDNs and cloud load balancers will accept IPv6 for you and speak IPv4 to your servers.

Routing: getting a packet there

No device on the internet knows the complete path to every destination. Each router knows only which of its neighbors is the best next step, and forwarding proceeds one hop at a time.

A router holds a routing table: a list of address blocks, each with the neighbor to forward to. To forward a packet it finds the entries that contain the destination address and picks the most specific, the one with the longest prefix. This is longest-prefix match. If both 203.0.113.0/24 and 203.0.0.0/16 match, the /24 wins. An entry for 0.0.0.0/0, the default route, matches everything and catches whatever nothing else did.

Your laptop has such a table too, with two useful entries: its own subnet, reachable directly, and a default route pointing at the local router.

Seeing the hopsEvery packet carries a counter, the TTL in IPv4 or hop limit in IPv6, that each router decreases by one. At zero the packet is discarded and the router reports back. This stops packets circling forever. The traceroute tool exploits it by sending packets with a limit of 1, then 2, then 3, and listing which router complains each time.

BGP: how separate networks cooperate

The internet is a network of networks. Each large independently run network, such as an internet provider, a cloud or a big company, is an autonomous system (AS) with a number. In October 2026 there were about 79,600 of them, exchanging routes for roughly 1.09 million address blocks.

They exchange those routes with the Border Gateway Protocol (BGP). Each AS announces to its neighbors the address blocks it can reach, along with the chain of ASes the route passes through. A neighbor that hears several routes to the same block chooses one by its own rules, which are as much commercial as technical: a route through a paying customer is preferred to one that costs money. It then passes its choice on.

BGP was designed for a small community of operators who knew each other, and it accepts announcements on trust. Two kinds of accident follow from that, and both have taken large services offline.

  • A network announces something it should not. In a route leak or hijack, an AS announces another network’s block, by mistake or on purpose, and part of the internet starts sending that traffic to the wrong place.
  • A network withdraws something it needs. On 4 October 2021 a maintenance command at Facebook disconnected its data centers from its own backbone. Its DNS servers, unable to reach the data centers, withdrew their BGP announcements as designed. Facebook’s names stopped resolving for the whole world, and its services were unreachable for about six hours. Recovery was slowed because the internal tools needed to fix the problem depended on the same network.

The defense against false announcements is RPKI (resource public key infrastructure), in which the owner of a block publishes a signed statement of which AS may announce it, and other networks reject announcements that contradict it. By mid-2026 about two-thirds of announced blocks were covered by such statements. It is a large improvement, and it does not help with the second kind of accident, which is self-inflicted.

In production. You will probably never configure BGP. You still depend on it for every request, and its failures look like nothing else: your servers are healthy, your monitoring from inside shows green, and some or all of the world cannot reach you. Monitor from outside your own network, from several places, and keep a way to manage your systems that does not depend on the network you are trying to fix.

Anycast: one address in many places

Normally an address belongs to one machine in one place. Nothing in BGP requires that. If the same block is announced from data centers on three continents, every network simply routes toward whichever announcement looks closest. This is anycast.

Anycast gives three things at once. Users reach a nearby site, which lowers latency. If a site fails and stops announcing, routing carries its users to the next nearest within seconds to minutes, with no DNS change. And a flood of attack traffic is split among all the sites according to where it originates, so no single site receives the whole of it.

It is how the DNS root servers, public resolvers such as 1.1.1.1 and 8.8.8.8, and most CDNs are reached. Its limitation is that routing can change in the middle of a conversation, sending later packets of a connection to a different site that knows nothing about it. That is harmless for a one-packet DNS query. For long connections it has to be engineered around, which CDNs do. returns to it.

A cloud network, drawn once

When you rent machines in a cloud you also design a small private internet for them, usually called a virtual private cloud (VPC) or virtual network. The products differ by provider and the shape is nearly always the same.

PieceWhat it is
Virtual networkA private address block, such as 10.0.0.0/16, that is yours alone.
SubnetA slice of that block, placed in one availability zone. You create matching subnets in two or three zones so that each tier survives the loss of a zone.
Public subnetA subnet whose route table sends 0.0.0.0/0 to an internet gateway. Resources here can have public addresses.
Private subnetA subnet whose default route goes to a NAT gateway, or nowhere. Nothing outside can start a connection to it.
Security group or firewall ruleA list of what may connect to a resource. Good ones name the source by role: “the database accepts port 5432 from the application servers’ group”, not from an address range.
Peering and private linksWays to join two virtual networks, or to reach a managed service, without crossing the public internet.

Two decisions here are hard to change later, so they deserve a moment early.

Choose address blocks that do not overlap. Two networks can be joined only if their ranges are distinct. If every environment and every team picks 10.0.0.0/16 because it is the default in the tutorial, none of them can ever be connected to each other or to an office network that uses the same range. Keep one plan for the whole organization and give each network its own block.

Make subnets bigger than you think you need. Containers and serverless functions can each consume an address, and a subnet cannot be enlarged once things are running in it. Private address space costs nothing, so be generous.

Packet sizeA link has a maximum packet size, its MTU, which is 1,500 bytes on ordinary Ethernet. Tunnels and VPNs add their own headers and so leave less room. When a path’s limit is lower than a sender assumes and the error messages that would report it are blocked by a firewall, small requests work and large ones hang without explanation. If you see exactly that pattern, suspect the MTU.

What this means for design

  • An IP address is a weak identity. It may stand for one person or for fifty thousand behind a NAT, and with IPv6 one person may have billions. Use it as one signal among several for rate limiting and abuse detection, and never as proof of who someone is.
  • The client’s address is easy to lose. Behind a load balancer or CDN, your server sees the address of that intermediary. The original is passed along in a header such as X-Forwarded-For, which is trustworthy only when your own infrastructure set it. covers this.
  • Private by default. Give public addresses only to the entry points. It reduces the attack surface and the bill.
  • Outbound traffic needs design too. Calls to third-party APIs leave through NAT, which has port limits, costs money and presents one source address that the third party may need to allow.
  • Distance is set by routing, not geography. Two cities that are close on a map may be connected through a third far away. Measure latency between regions before assuming it.

Key points

  • The network is layered. IP, at layer 3, moves packets between networks on a best-effort basis and knows nothing about connections or requests.
  • An address is a network prefix plus a host part. CIDR notation gives the prefix length, and each extra bit halves the block.
  • IPv4 addresses ran out. Private ranges with NAT, a market in addresses, and IPv6 are the three responses, and all three are in use.
  • NAT means connections start from inside, many users share an address, idle connections are dropped and ports can run out.
  • IPv6 removes scarcity. Store addresses properly, limit by /64, and serve both protocols.
  • Routing is hop by hop with longest-prefix match. BGP joins independent networks on trust, and its failures make healthy services unreachable.
  • Anycast announces one address from many sites to give proximity, failover and attack absorption.
  • In a cloud network, only entry points are public, address blocks must not overlap, and subnets should be sized generously.

Check yourself

How many addresses are in 10.20.0.0/22, and what is the last one?

A /22 leaves 10 host bits, so 210 = 1,024 addresses. The block runs from 10.20.0.0 to 10.20.3.255.

Your API blocks any IP address that makes more than 100 requests a minute. A university complains that all its students are locked out. What happened?

The university’s students reach the internet through NAT and share a small number of public addresses. Together they exceeded the limit that was meant for one client. Limit by something that identifies the client, such as an API key or account, and use the address only as a coarse backstop with a much higher threshold.

A service keeps a connection to a database open and uses it once every twenty minutes. The first query after each pause fails. Why, and what are two fixes?

A NAT gateway or firewall on the path removed the idle connection’s entry from its table, so the next packet matches nothing. Either send keepalives more often than the idle timeout, or have the connection pool test and replace idle connections before using them.

Two teams each built a virtual network using 10.0.0.0/16. They now need their services to talk privately. What is the problem?

The ranges overlap, so the networks cannot be peered: a packet for 10.0.5.9 could belong to either side. One network has to be rebuilt on a different block, or the teams must connect through public endpoints or a translating gateway. An organization-wide address plan would have prevented it.

Your monitoring, which runs inside your own data center, shows everything healthy. Customers report that the site is unreachable. Name a cause at the layer discussed in this chapter.

A routing problem: your address block is no longer announced, is being announced by someone else, or a network between you and the customers has lost its route. Internal monitoring cannot see it because it never leaves your network. Probes from outside, in several locations, would.

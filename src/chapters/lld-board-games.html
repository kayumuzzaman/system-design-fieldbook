The problem

The problem. Design the classes for a two-player board game: tic-tac-toe first, then chess. Players take turns. The program accepts legal moves and refuses the rest, knows when the game is over and why, lets a player take a move back, and offers a computer opponent.

describes a game as “polymorphic pieces, a board that validates moves, and a turn-taking state machine.” All three appear here, though not where a first sketch puts them. The polymorphism that pays is between games: one interface lets the same match, undo and computer player serve both. The board that validates moves becomes a position that knows more than the board, because chess’s hard rules depend on the game’s history. The state machine is small: a game is ongoing until it is won or drawn.

Step 1: Clarify

QuestionAssumed answer for this design
Which games?Tic-tac-toe on a square board of any size, won by a full row, column or diagonal. Chess under the FIDE Laws, every kind of move included
Who plays?Two players, each a person or the computer. The core does not know which
What can a player do?Make a move, or take the last one back. Resigning, draw offers and clocks are follow-ups
How is a move written?A square number for tic-tac-toe. For chess, two squares and any promotion piece, as chess programs write it: e2e4, e7e8q
When does a game end?Tic-tac-toe: a full line or a full board. Chess: checkmate, stalemate, fifty moves without a capture or pawn move, the same position three times, or too little material to mate

One answer hides a decision. Under the FIDE Laws, three repetitions or fifty moves let a player claim a draw, and only five repetitions or 75 moves end the game on their own. With nobody to make the claim, this design ends the game at the first threshold, and every result carries its reason.

The first invariant decides who owns play: only the state can tell a legal move from an illegal one, so the match, the players and the user interface all ask it, and none repeats a rule.

Step 4: The classes

The interface has two type parameters: M, the type of a move, a number for tic-tac-toe and a Move for chess; and G, the implementing class itself, so that play on a Position returns a Position and not a vague Game. That is what G extends Game<M, G> says.

The states are values in the sense of : play returns a new state and leaves the old one as it was. Undo becomes dropping the last state. A search tries a move and walks away, with nothing to reverse on an early return. States can be shared between a match, a search and threads with no locks. The price is a copy on every move, weighed later in the chapter.

Step 6: The code

The contract, and a match for any game

export interface Game> {
  readonly toMove: string;          // whose turn it is, such as "X" or "white"
  legalMoves(): M[];
  play(move: M): G;                 // the state after the move; throws IllegalMove if it is not allowed
  outcome(): Outcome;
  describe(move: M): string;        // for history and error messages
}

export class IllegalMove extends Error {}

// A match: a game in progress, its history, and undo. It works for any game that fits the interface.
export class Match> {
  private readonly states: G[];
  private readonly moves: string[] = [];

  constructor(start: G) {
    this.states = [start];
  }

  get current(): G {
    return this.states[this.states.length - 1] as G;
  }
  get history(): readonly string[] {
    return this.moves;
  }

  play(move: M): Outcome {
    const now = this.current.outcome();
    if (now.kind !== "ongoing") throw new IllegalMove("the game is over");
    const next = this.current.play(move); // the game decides what is legal; the match only keeps the record
    this.moves.push(this.current.describe(move));
    this.states.push(next);
    return next.outcome();
  }

  undo(): void {
    if (this.states.length === 1) throw new Error("nothing to undo");
    this.states.pop();
    this.moves.pop();
  }
}

outcome returns ongoing, a win with its winner, or a draw, each with a reason. Match knows nothing about either game: it refuses a move once the game is over, lets the state judge the move, and keeps the record. A Player is one method, choose(game).

Tic-tac-toe: a win check that does not read the board

The obvious win check scans all 2n + 2 lines of an n by n board after every move. But a move can only complete a line through its own square: its row, its column, and a diagonal or two. So each line keeps a running count, plus one for every X and minus one for every O. A line at n holds n X; one at −n holds n O.

play(square: number): TicTacToe {
    if (this.winner || this.filled === this.n * this.n) throw new IllegalMove("the game is over");
    if (!Number.isInteger(square) || square < 0 || square >= this.n * this.n) throw new IllegalMove(`no square ${square}`);
    if (this.cells[square] !== null) throw new IllegalMove(`square ${square} is taken`);
    const { n } = this;
    const r = Math.floor(square / n), c = square % n, d = this.toMove === "X" ? 1 : -1;
    const cells = [...this.cells]; cells[square] = this.toMove;
    const rows = [...this.rows]; rows[r] = (rows[r] as number) + d;
    const cols = [...this.cols]; cols[c] = (cols[c] as number) + d;
    const diagonals: [number, number] = [this.diagonals[0] + (r === c ? d : 0), this.diagonals[1] + (r + c === n - 1 ? d : 0)];
    const won = [rows[r], cols[c], ...diagonals].some((count) => Math.abs(count as number) === n); // only lines through this square can have changed
    return new TicTacToe(n, this.toMove === "X" ? "O" : "X", cells, rows, cols, diagonals, won ? this.toMove : null, this.filled + 1);
  }

The test walked the whole game tree from the empty board: 549,946 positions counting repeats, 5,478 of them different, 958 where the game is over, and 255,168 different games, all four matching published counts. On every different position the counters agreed with a plain scan of the eight lines.

Chess: how the pieces move

The board is an array of 64 squares, a1 being 0 and h8 63. A helper, step, moves a square by some files and ranks, or returns −1 off the board.

// How each piece moves, as data: a set of directions, and whether it may keep going in a direction.
// The pawn is the exception, and has its own code below.
type Dir = readonly [number, number];
const ORTHOGONAL: Dir[] = [[1, 0], [-1, 0], [0, 1], [0, -1]];
const DIAGONAL: Dir[] = [[1, 1], [1, -1], [-1, 1], [-1, -1]];
const KNIGHT: Dir[] = [[1, 2], [2, 1], [2, -1], [1, -2], [-1, -2], [-2, -1], [-2, 1], [-1, 2]];
export const MOVEMENT: Record, { dirs: Dir[]; slides: boolean }> = {
  n: { dirs: KNIGHT, slides: false },
  b: { dirs: DIAGONAL, slides: true },
  r: { dirs: ORTHOGONAL, slides: true },
  q: { dirs: [...ORTHOGONAL, ...DIAGONAL], slides: true },
  k: { dirs: [...ORTHOGONAL, ...DIAGONAL], slides: false },
};

// Moves that follow how the pieces move, without asking whether they leave the king in check.
  pseudoLegalMoves(): Move[] {
    const moves: Move[] = [];
    const us = this.turn;
    for (let from = 0; from < 64; from += 1) {
      const piece = this.board[from];
      if (!piece || piece.color !== us) continue;
      if (piece.kind === "p") { this.pawnMoves(from, moves); continue; }
      const { dirs, slides } = MOVEMENT[piece.kind];
      for (const [df, dr] of dirs) {
        for (let to = step(from, df, dr); to >= 0; to = slides ? step(to, df, dr) : -1) {
          const there = this.board[to];
          if (there && there.color === us) break;
          moves.push({ from, to });
          if (there) break;
        }
      }
    }
    this.castlingMoves(moves);
    return moves;
  }

A piece walks each of its directions, once or until something stops it. Its own piece blocks the square; an enemy piece can be taken, and ends the slide. These are the pseudo-legal moves: the moves the pieces’ movement allows, before asking whether they leave the mover’s own king attacked. The pawn has its own function, because its moves differ in kind: forward to move, diagonal to capture, two squares from its first rank, en passant, and one move for each piece it may become on the last rank. The Laws make promotion part of the move (article 3.7.3.3), so a move to the last rank that names no piece is refused.

Legal moves: the rule no piece knows

// The rule that no piece knows about: a move may not leave your own king attacked.
  legalMoves(): Move[] {
    return this.pseudoLegalMoves().filter((m) => {
      const next = this.apply(m);
      return !next.isAttacked(next.kingSquare(this.turn), next.turn);
    });
  }

  play(move: Move): Position {
    const legal = this.legalMoves().find((m) => m.from === move.from && m.to === move.to && (m.promotion ?? null) === (move.promotion ?? null));
    if (!legal) throw new IllegalMove(`${this.describe(move)} is not legal here`);
    return this.apply(legal);
  }

A move is legal if, in the position after it, the mover’s king is not attacked. isAttacked looks outward from the king’s square: along lines and diagonals for sliding pieces, a knight’s jump away, one step for a king or pawn. The same function decides check and whether castling is safe.

Castling follows article 3.8 of the Laws. The right is lost for good once the king has moved, or the rook in question. It is prevented for now if a square between them is occupied, or if the square the king stands on, crosses or lands on is attacked. The rights are the letters of FEN, KQkq. apply removes them when a king moves, and when anything leaves or lands on a rook’s starting square, which covers a rook captured at home. The tests check castling allowed, refused through f1, lost after h1h2, and lost by both sides when a rook takes a rook on a8. En passant is allowed only on the move right after the double step (article 3.7.3.2): the position records the skipped square, apply clears it after every other move, and the test checks that the capture works at once and is refused once each side has moved again.

Endings, and what counts as the same position

outcome looks first for a side with no legal moves: checkmated if in check, stalemated if not. Mate comes first because a move that gives mate stands even if it also completes the 75th move (article 9.6.2). halfmoves counts moves by either side since the last capture or pawn move, so 100 is fifty each. The material check knows only the simplest cases: kings alone, or a king with one bishop or knight against a lone king. The Laws’ rule is wider, a dead position from which no series of legal moves can lead to mate, and is a follow-up.

Repetition is counted in seen, a map from each position’s key to how often it has occurred. No position before a capture or pawn move can occur again, so apply starts the map afresh after one. Article 9.2.3 defines “the same position”: the same player to move, the same pieces on the same squares, and the same possible moves for both players. So a key built from the FEN fields is subtly wrong. FEN records the en passant square after every double step, whether or not any pawn can use it, and with that in the key the position after 1. e4 can never repeat. key() includes the square only when a pawn of the side to move stands beside it. The test plays 1. e4 and moves both knights out and back twice: the position after 1. e4 has occurred three times, and the game is drawn. A second test checks that where a capture was possible, the first occurrence does not count.

Testing the move generator

Hand-written tests check the rules their author thought of. A chess move generator needs a test that does not depend on remembering every rule, and the chess programming community has one. Perft, short for “performance test, move path enumeration”, counts the positions reached after exactly a given number of moves, following every legal move at every step. Counts for standard positions are published, and a single wrong rule changes a number somewhere.

// Counts the positions reached after exactly `depth` moves. Published counts for standard positions make this
// the usual test of a chess move generator: a single wrong rule changes a number somewhere.
export function perft(position: Position, depth: number, legal = true): number {
  const moves = legal ? position.legalMoves() : position.pseudoLegalMoves();
  if (depth === 1) return moves.length;
  let total = 0;
  for (const m of moves) total += perft(position.apply(m), depth - 1, legal);
  return total;
}

The positions are given in Forsyth–Edwards Notation, or FEN, one line of text that describes a whole chess position: the pieces rank by rank from the eighth, the side to move, the castling rights, the en passant square, the count toward the fifty-move rule, and the move number. David Forsyth devised it in the nineteenth century, and Steven Edwards specified it for computers as part of Portable Game Notation.

The test also shows what perft catches. Counted with pseudo-legal moves, the start position gives 20, 400 and 8,902, all correct, and then 197,742 at depth 4 instead of 197,281. The 461 extra positions all come from black’s second move, the first that can leave the mover’s own king attacked. The test sorts them: 245 ignore a check, 188 move a pinned piece, and 28 walk the king into an attack. A bug in a rare rule shows the same way. To find it, chess programmers split the count by first move, a variant called divide, compare each part with a trusted program’s, and repeat one move further down.

A computer player for either game

A game tree has a position at every node and a move on every edge, from the current position down to positions where the game is over or the search stops. Minimax gives each position the value of the best result its player can force against an opponent who also plays its best. Negamax writes minimax once for both players: every value is from the point of view of the side to move, so a position is worth the largest of its children’s values with their signs flipped.

// Negamax with alpha-beta pruning, for any game that fits the interface. The score is from the point of view of
// the side to move: positive is good for it. Wins found sooner score higher, so the search prefers the quickest.
export function search>(game: G, depth: number, evaluate: (g: G) => number, alpha = -Infinity, beta = Infinity, ply = 0): number {
  const outcome = game.outcome();
  if (outcome.kind === "win") return -(WIN - ply); // the side to move has lost
  if (outcome.kind === "draw") return 0;
  if (depth === 0) return evaluate(game);
  let best = -Infinity;
  for (const move of game.legalMoves()) {
    const score = -search(game.play(move), depth - 1, evaluate, -beta, -alpha, ply + 1);
    if (score > best) best = score;
    if (best > alpha) alpha = best;
    if (alpha >= beta) break; // the opponent will never allow this line, so the rest need not be looked at
  }
  return best;
}

A loss scores a large negative number, smaller for each move it took, so the search prefers quicker wins; a draw is zero; when the depth runs out, evaluate guesses. Alpha-beta pruning computes the same value as minimax while skipping moves that cannot change it: alpha is what the side to move is already sure of, beta the most the opponent will allow, and once a move reaches beta, the opponent would never let the game get here, so the remaining moves are not looked at.

Searched to the end, the empty board is worth 0: perfect play by both sides is a draw. In 400 games against a player choosing at random, with sides alternating, the search won 366, drew 34 and lost none. Plain minimax from the empty board visits all 549,945 positions below it; this search visited 20,865 with squares tried in order, and 8,829 with winning moves tried first. Nothing in search.ts mentions either game: given chess and a count of material for evaluate, it searched two moves deep and found the test’s two mates, h5f7 and a1a8.

How much alpha-beta saves depends on move order. Tried worst first, it saves nothing. Tried best first in a tree where every position has b moves, it examines b⌈d/2⌉ + b⌊d/2⌋ − 1 leaves at depth d instead of bd. The count is credited to Michael Levin in 1961; Donald Knuth and Ronald Moore published the classic analysis in 1975. With about 35 moves in an average chess position, six moves deep is 1.84 billion leaves for minimax and 85,749 for alpha-beta at its best.

At 6 moves deep, minimax examines 1.84 billion leaves and alpha-beta at its best 85,749. At about 200,000 positions a second, that is 2.55 hours against 429 ms. For the work minimax does here, alpha-beta at its best reaches 10 moves deep.

The zigzag is real; chess programmers call it the odd-even effect. From an even depth to the next odd one the count grows by about (b + 1) ÷ 2, and from odd to even by about 2. Two moves deeper costs a factor of b, against b² for minimax, so for the same work alpha-beta at its best searches nearly twice as deep. Programs get near the best case by ordering moves: captures and checks first, and the best move from a shallower search before the rest.

Immutable states, and their cost

Every move here copies the position: 64 squares, a few fields, and the map of positions seen since the last capture or pawn move. Programs built for speed keep one board instead: they make a move on it, search below, and unmake the move, saving on a stack what cannot be worked out backward, such as the castling rights, the en passant square, the fifty-move count and the captured piece.

Keep every state, as hereMake and unmake on one board
UndoDrop the last stateReverse the move from what was saved

These are the two ways to undo from : a snapshot of each state, or a command that reverses itself. Where people play, the snapshot wins on simplicity; for an engine searching millions of positions a second, the reversal wins on speed. Also, play checks each move against the full list of legal moves, right for moves from a person and wasted inside a search, so perft calls apply directly.

Step 7: Walk it

Follow white castling on the king’s side in a match that starts from kings and rooks only, all four rights intact.

  1. The interface calls match.play(uci("e1g1")). The match asks the position for its outcome: there are legal moves and no draw by rule, so the game is ongoing.
  2. The position lists its pseudo-legal moves. The king’s row in MOVEMENT gives eight one-step directions. castlingMoves finds the right K, f1 and g1 empty, and none of e1, f1 and g1 attacked, and adds e1g1 with the flag castle.
  3. Each pseudo-legal move is applied and kept only if white’s king is not attacked afterward. e1g1 survives, and play applies it: the king to g1 and, because of the flag, the rook from h1 to f1. White loses both rights, leaving kq, and the fifty-move count rises to 1.
  4. The match records e1g1 and the new position. Had a black rook stood on f8, step 2 would have found f1 attacked, and the match would have thrown IllegalMove with nothing recorded.

Key points

  • Put the polymorphism between games: one interface lets one match, one undo and one search serve both. Make its states immutable, so undo is dropping a state and a search cannot damage the game.
  • Check for a win only on the lines through the last move. Line counters agreed with a full scan on all 5,478 tic-tac-toe positions.
  • Describe how pieces move as data, and keep the rules in the position. Pins, check, castling and en passant depend on pieces other than the one moving.
  • A legal move is a pseudo-legal move that leaves the mover’s king safe. Without that filter, perft from the start was right for three moves and wrong at the fourth.
  • Test a move generator with perft. This one matched the published counts for five standard positions.
  • Alpha-beta returns the minimax value from far fewer positions, and move ordering decides how many.

Check yourself

Why does play return a new state instead of changing the board?

So the old state is still there: undo drops the newest state, a search discards what it tried with nothing to reverse, and states are shared without locks. The price is a copy on every move.

A bishop on e2 can reach nine squares, yet it has no legal move. How does the code find that out?

Its movement gives nine pseudo-legal moves. legalMoves applies each and asks whether white’s king is then attacked. After every one, a rook on e8 sees down the open e-file to the king on e1, so all nine are dropped.

In a design with a class for each kind of piece, where would the castling rule go, and why is that awkward?

Castling needs an unmoved king and rook, empty squares between them, and three squares no enemy piece attacks. King.moves would need the whole position, so the rule ends up in a board or game class anyway.

Your move generator gives 20, 400, 8,902 and then 197,742 from the start position. The published count at depth 4 is 197,281. What is the likely bug?

It allows moves that leave the mover’s own king attacked. Black’s second move is the first that can, by ignoring a check, moving a pinned piece or walking into an attack. This chapter’s code gives exactly that count without the king check.

Tic-tac-toe is played on a 100 by 100 board, won by a full line. How much work is the win check after a move, with and without line counters?

A full scan reads 202 lines of 100 squares, about 20,000 cells. With counters, the move changes and compares at most four counts, whatever the size.

With 35 moves in every position, how many leaves does alpha-beta examine at depth 4 in its best case, and how many does minimax?

35² + 35² − 1 = 2,449 for alpha-beta, against 35⁴ = 1,500,625 for minimax. With the worst move tried first, alpha-beta examines as many as minimax.

After 1. e4, both players move a knight out and back twice. Has the position after 1. e4 now occurred three times?

Yes. Positions are the same when the same player is to move, the same pieces stand on the same squares and the same moves are possible. No black pawn can take e4 en passant, so the e3 square that FEN records makes no difference. A key that always includes it misses the draw.
